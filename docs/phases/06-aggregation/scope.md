# 6단계 범위

## 목표

상품 리뷰 요약과 월별 주문 집계 쿼리를 기준 상태, 단순 인덱스, 쿼리 형태 맞춤 인덱스 측정 조건에서 비교한다.

## 포함 범위

| 영역 | 범위 |
|---|---|
| SQL 전용 대상 1 | 상품 리뷰 요약: `product` + `review` |
| SQL 전용 대상 2 | 월별 주문 집계: `orders` + `users` |
| API 대상 | `GET /api/products/review-summary` |
| 인덱스 측정 조건 | 기준 상태, 단순 인덱스, 쿼리 형태 맞춤 인덱스 |
| SQL 증거 | `EXPLAIN (ANALYZE, BUFFERS)` |
| API 증거 | 리뷰 요약 API k6 단순 인덱스/쿼리 형태 맞춤 인덱스 비교 |
| 데이터 프로파일 | 행 수, 리뷰 분포, 월별 주문 분포, 인덱스 상태 |

## 제외 범위

- 6단계 전용 인덱스를 `docker/postgres/init.sql`에 추가하지 않는다.
- 상품 리뷰 요약 API에 요청 파라미터를 추가하지 않는다.
- QueryDSL로 상품 리뷰 요약 API를 구현하지 않는다.
- 모든 SQL 측정 조건을 k6로 반복하지 않는다.
- 페이지네이션 최적화는 7단계로 남긴다.

## 완료 조건

- [ ] `product`, `review`, `orders`, `users` 행 수와 리뷰/월별 주문 분포를 증거로 기록했다.
- [ ] 6단계 SQL 전용 증거를 재현할 수 있는 번호 기반 `scripts/phase-06/*.sql` 파일을 작성했다.
- [ ] 측정 조건별 `prepare` SQL에서 전용 인덱스 상태, `VACUUM (ANALYZE)`, `pg_stat_statements_reset()` 실행 조건을 분리했다.
- [ ] 상품 리뷰 요약 집계 쿼리를 기준 상태, 단순 인덱스, 쿼리 형태 맞춤 인덱스 측정 조건에서 비교했다.
- [ ] 월별 주문 집계 쿼리를 기준 상태, 단순 인덱스, 쿼리 형태 맞춤 인덱스 측정 조건에서 비교했다.
- [ ] 각 측정 조건의 `EXPLAIN (ANALYZE, BUFFERS)`를 `docs/evidence/phase-06/` 아래에 저장했다.
- [ ] 상품 리뷰 요약 API를 단순 인덱스 조건과 쿼리 형태 맞춤 인덱스 조건에서 k6로 비교했다.
- [ ] `HashAggregate`, `GroupAggregate`, `Sort`, 스캔 방식 변화와 실행시간 차이를 보고서에 해석했다.
- [ ] `DATE_TRUNC` 표현식 인덱스의 생성 가능 여부, 플래너 사용 여부, 실행시간 차이를 기록했다.
- [ ] 7단계 페이지네이션 병목과 6단계 집계 쿼리 병목을 분리해 인계 내용을 기록했다.
